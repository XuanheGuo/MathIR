# Matherium Rational-Function Integration

Provider `mathir-validator@0.3.0` speaks Matherium Protocol `0.2.0` and adds two deterministic synchronous capabilities:

- `mathir.normalize-rational-function@0.1.0`
- `mathir.check-rational-function-equivalence@0.1.0`

The existing validation and polynomial capability wire contracts remain unchanged. The registry contains exactly five capabilities sorted by ID and version with code-unit comparison. Authentication remains `none`.

Both new inputs are strict Draft 2020-12 objects. `document` accepts any JSON value so full MathIR validation occurs inside execution; `assumptionMode` is required and is exactly `ignore` or `document_nonzero`. Malformed wrappers are HTTP 422. Algebra outcomes—including unsupported, unknown, conditional, and invalid-document outcomes—are successful Matherium Invocations; only sanitized internal failures become `ExecuteFailure`.

Outputs expose fixed rational and assumption semantics, canonical value normal forms, original left/right domain guards, the additional required guard, condition status, categorized assumption IDs, stable issues, and validation diagnostics. Zod runtime schemas and Ajv 2020 strict JSON Schemas independently accept generated examples and actual outputs. Manifest examples are generated by the execute functions, so they cannot drift from implementation.

The algebra layer limits each rational-function normal form to 300 KiB. Guard degree and assumption count have independent bounds. Provider serialization remains at most 900 KiB UTF-8; it never truncates a numerator, denominator, guard, or assumption list. Validation diagnostics alone retain the existing marked stable-prefix bounding behavior.

`pnpm test:matherium-conformance` runs the unmodified external suite pinned at `73b02d660fa1d62140b4c0efacbf5274804b1e8b`. `pnpm test:matherium-e2e` uses the real Hub and PostgreSQL and verifies all five registrations plus validation/polynomial regressions, rational cancellation normalization, conditional equivalence, assumption discharge, same-domain equivalence, non-equivalence, multivariate unknown, and invalid-document behavior. Each case checks succeeded Invocation state, events, immutable JSON Artifact content and schema, and producer provenance.

The result is exact univariate rational-function equivalence over `Q(x)` with explicit domain provenance. It is not general mathematical equivalence, root-aware reasoning, or arbitrary assumption substitution.
